# 持仓分析快照设计

## 目标

为每位登录用户的每条持仓保存最新一次分析结果。持仓列表以显式 `>` 与 `∨` 控制展开；展开时读取已保存的结果，不自动重新请求行情。执行客观分析或 AI 分析后，保存结果并覆盖该持仓原有快照。

## 交互

- 持仓行首显示 `>`（收起）或 `∨`（展开），不显示“展开分析 / 收起分析”文本。
- 点击 `>` 时，请求该持仓最近快照并展开。没有快照时显示提示与“分析”入口。
- 点击 `∨` 时只收起，不清除本页缓存。
- “分析”执行不调用大模型的客观指标分析，刷新并保存技术指标和持仓计算数据；若已有 AI 报告，保留其内容。
- 面板内“AI 分析”调用 DeepSeek，保存完整报告并覆盖同一持仓的 AI 部分。
- 任何写入均以 `(user_id, position_id)` 为唯一键；下一次同类分析覆盖上一次数据。

## 后端

新增 `stock_position_analysis_snapshot` 表，字段包含用户、持仓、序列化的分析 JSON、分析时间与审计字段，并在 `(user_id, position_id)` 上建立唯一索引。

新增快照 domain、mapper、service。服务按当前用户与持仓查询和 upsert，不允许跨用户读取或覆盖。

持仓控制器增加获取最新快照接口。现有分析接口在计算技术指标、实际大盘趋势与持仓数据后写入快照：客观分析从旧快照保留 AI 文本，AI 分析则保存新生成的 AI 文本。

## 前端

持仓 API 增加读取快照方法。持仓页保留受控展开行，增加可见的窄图标列作为展开控制；加载列表后不预取快照，首次展开时按持仓 ID 懒加载。

已有报告按持仓 ID 缓存在页面中。客观分析、AI 分析完成后均以接口返回结果更新缓存，保证当前面板立即展示已保存版本。

## 异常与测试

- 无快照返回空结果，前端展示“暂无已保存分析”。
- 非本人持仓沿用现有用户范围校验并拒绝访问。
- 快照 JSON 异常或外部行情 / AI 调用失败沿用现有接口错误处理，不写入不完整结果。
- 新增快照服务单测，覆盖用户隔离、首次保存与覆盖保存；保留持仓分析与前端构建验证。
