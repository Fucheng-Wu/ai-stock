# 股票管理三页统一 UI 改造设计

## 1. 目标与范围

统一重做股票管理模块下的三个页面：

- AI 分析报告：`ruoyi-ui/src/views/stock/analyzer/index.vue`
- 我的自选：`ruoyi-ui/src/views/stock/watchlist/index.vue`
- 我的持仓：`ruoyi-ui/src/views/stock/position/index.vue`

视觉方向采用已确认的 A 方案「清爽科技蓝」：浅色背景、克制卡片、清晰数据层级、蓝色主操作，整体参考成熟互联网企业后台产品。改造仅涉及前端展示、布局和交互反馈；沿用当前 API、权限标识、路由参数与后端数据结构。

## 2. 设计原则

1. **统一**：三页共享颜色、间距、圆角、阴影、标题、指标卡、状态标签和空状态规范。
2. **数据优先**：价格、涨跌、盈亏、仓位和交易信号优先于说明文字，关键数字采用等宽数字表现。
3. **克制用色**：品牌蓝仅用于主操作和选中态；按 A 股习惯使用红涨绿跌，并同时提供文字或图标语义。
4. **渐进披露**：列表默认展示决策所需信息，详细技术分析和 AI 报告通过展开区域呈现。
5. **响应式**：桌面端保持专业信息密度；窄屏时指标自动换行、操作区堆叠，表格保留必要横向浏览能力。
6. **兼容现状**：继续使用 Vue 2.6 与 Element UI 2.15，不引入新的 UI 依赖。

## 3. 共用视觉系统

### 3.1 页面框架

每页采用同一信息骨架：

1. 页面标题区：模块标题、简短说明、右侧主要操作。
2. 概览区：当前页面最重要的 3–4 个指标。
3. 主内容区：分析结果、股票列表或持仓列表。
4. 详情区：技术指标、交易信号、AI 结论和风险提示。

### 3.2 样式变量

在股票模块中定义局部设计变量，避免影响若依其他页面：

- 主色：`#2563EB`
- 主色浅背景：`#EFF6FF`
- 页面背景：`#F5F7FA`
- 卡片背景：`#FFFFFF`
- 主文本：`#172033`
- 次文本：`#667085`
- 边框：`#E7EAF0`
- 上涨：`#E5484D`
- 下跌：`#16A36A`
- 警告：`#F59E0B`
- 圆角：卡片 10px、控件 8px、标签 999px
- 阴影：仅用于主要卡片的轻量层次，不使用大面积渐变和重阴影

使用统一 CSS 类承载页面标题、内容卡、指标卡、状态点、涨跌色、空状态和移动端断点。共享样式独立放在股票模块样式文件中，由三个页面分别引入。

### 3.3 交互状态

- 加载：保留 Element UI loading，并提供有意义的加载文案和稳定的最小高度。
- 空状态：使用图标、说明和明确主操作，不展示空白表格或空卡片。
- 错误：页面内错误提示保留重试上下文，不清除用户已输入内容。
- 操作反馈：保存、删除和分析继续使用现有消息组件；危险操作使用红色文字或按钮。
- 展开详情：同一时间仅展开一行，保留现有行为；展开区使用独立信息分组，不再堆叠普通段落。

## 4. 页面设计

### 4.1 AI 分析报告

页面由以下区域组成：

1. **分析入口**：左侧标题与说明，右侧为股票代码输入框和“开始分析”主按钮；支持回车和清空。
2. **股票行情头部**：展示股票名称、代码、当前价、涨跌额、涨跌幅和更新时间；去除大面积紫色渐变。
3. **行情指标**：开盘、昨收、最高、最低、成交量、成交额以六宫格指标展示。
4. **策略判断**：均线数据与交易信号并排展示；交易信号拥有最高视觉权重，置信度与建议仓位采用轻标签。
5. **AI 报告**：将操作建议作为摘要条，风险等级靠近标题，分析理由使用易读的正文区域。
6. **纪律提醒**：六条规则改为紧凑编号列表，弱化装饰，强化可扫描性。

未分析时显示产品化空状态，解释支持的代码格式和分析输出内容。

### 4.2 我的自选

页面由以下区域组成：

1. **标题与新增入口**：标题区展示自选数量；新增表单使用紧凑工具条布局。
2. **自选列表**：代码与名称组成主标识列，加入时间作为次要信息；操作区提供“分析”和“移除”。
3. **分析展开区**：顶部为行情摘要；中部为行情指标和均线；下部为交易信号、纪律提醒和 AI 分析入口。
4. **AI 报告**：仅在用户触发后加载，保留当前 `includeAi` 行为和单行加载状态。

列表为空时展示引导用户添加第一只股票的空状态。移除操作继续经过确认对话框。

### 4.3 我的持仓

页面由以下区域组成：

1. **资产概览**：展示账户总资产、持仓市值、可用/未配置资产提示、持仓数量等可由现有数据推导的信息；不伪造收益曲线。
2. **标题操作区**：账户总资产与新增持仓为清晰的次/主操作。
3. **持仓列表**：股票标识、成本价、数量、持仓比例和操作；数值右对齐，比例使用轻量进度表现。
4. **持仓展开区**：行情、MA5/MA20、趋势、交易信号、成本、市值、浮盈亏和量价指标分组展示。
5. **AI 报告**：通过独立按钮触发，结果使用与分析页相同的摘要和理由样式。
6. **编辑弹窗**：统一表单标签宽度、输入控件宽度、校验反馈和底部按钮层级。

账户总资产未配置时以提示态呈现，不把缺失值显示为正常指标。

## 5. 数据与组件边界

- 不修改 `ruoyi-ui/src/api/stock/*.js` 的请求地址与参数。
- 不修改后端 Controller、Service 或 Domain。
- 各页面保留现有请求时机和权限指令。
- 只添加纯展示计算属性与格式化方法，例如安全数字格式化、涨跌样式、信号文案和概览汇总。
- 对空值、非数字值和缺失的嵌套对象提供展示级兜底，避免模板运行时错误。
- 共用 CSS 负责视觉一致性；业务状态仍留在各自页面中，避免为本次改造引入跨页状态管理。

## 6. 错误处理与边界情况

- 股票代码为空时不发送请求，并保留输入焦点。
- 接口失败时展示服务端错误信息；没有信息时使用明确的默认文案。
- `stock`、`signal`、`holding` 或 `indicators` 部分缺失时，相关区域显示 `--` 或不渲染，不调用缺失值的 `toFixed`。
- 重复触发分析时由现有 loading 状态阻止视觉上的重复操作。
- 长股票名称、长 AI 文本和窄屏按钮需自动换行，不能遮挡或溢出。
- 表格在窄屏保留关键列，次要信息通过展开区获取。

## 7. 验证与验收

### 7.1 自动验证

- 执行前端生产构建，确保 Vue 模板和样式可编译。
- 检查三个页面没有新增 lint/编译错误。
- 搜索确认所有现有权限标识、API 调用和路由查询参数仍保留。

### 7.2 人工验收

- 三页在桌面宽度下具备一致的标题、卡片、指标和操作语言。
- 在约 768px 与 375px 宽度下无文本遮挡、按钮溢出或布局断裂。
- AI 分析页覆盖初始、加载、成功、失败四种状态。
- 自选页覆盖空列表、添加、展开分析、AI 分析和删除确认。
- 持仓页覆盖空列表、新增、编辑、账户资产配置、展开分析和 AI 分析。
- 红涨绿跌、信号、风险和盈亏在三页保持一致语义。

## 8. 非目标

- 不新增 K 线图、实时轮询、筛选排序或批量操作。
- 不修改 520 均线算法、AI 提示词或 DeepSeek 调用逻辑。
- 不调整若依全局导航、菜单结构或其他业务模块主题。
- 不增加新的第三方依赖。
