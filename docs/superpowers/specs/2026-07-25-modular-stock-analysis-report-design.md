# 股票分析结果六模块重构设计

## 1. 背景与目标

当前分析服务把趋势、主信号和 DeepSeek 输出压缩为一个综合结论，三个前端页面又分别维护近似但不一致的报告模板。这种结构无法同时展示金叉、回踩、均线粘合发散三类买点的独立证据，也无法在持仓场景中分别解释短线止损、趋势止损、常规止盈和强势止盈。

本次改造将分析结果重构为六个业务模块：

1. 基础信息；
2. 定趋势；
3. 找买点；
4. 止损；
5. 止盈；
6. 坚决不能犯的六个错误。

每次用户主动点击“分析”都直接生成确定性规则报告并调用一次 DeepSeek，不再保留二次“AI 分析”按钮。普通分析页和自选页只在 MA20 趋势向上时展示找买点；持仓页在此基础上始终增加止损与止盈。基础信息、定趋势和六个错误在任何成功或部分成功的报告中始终存在。

本系统输出用于规则化技术分析和风险提示，不构成收益承诺、投资建议或自动交易指令。

## 2. 已确认的产品决策

- 前端使用纵向完整报告，六个模块按决策顺序展开，不使用标签页或默认折叠隐藏证据。
- 股票分析页、自选页和持仓页共用同一个报告组件和同一份响应契约。
- 点击分析后直接调用 DeepSeek；删除现有二次 AI 按钮和前端 `includeAi` 交互。
- 一次 DeepSeek 请求携带当前场景应展示的全部指标，返回各模块、各子项的结构化结论。
- DeepSeek 只能解释服务端已计算的指标和规则状态，不能改变确定性结论。
- 当前量比采用腾讯实时行情源提供的标准盘中量比。
- “当日成交量 ÷ 前一日成交量”独立计算和展示，不得与标准量比混用。
- MA5、MA10、MA20、趋势、买点、止损和止盈只使用已完成日 K。
- 趋势、三类买点、两类止损和两类止盈沿用既有量化规则。
- DeepSeek 不可用时仍返回并展示确定性报告；对应 AI 区域显示不可用状态。
- 六个错误直接采用 `doc/520.txt` 的固定内容，不交给 AI 改写。

## 3. 总体架构

### 3.1 分析编排

分析流程统一为：

```text
用户点击分析
  -> 并行获取腾讯实时行情与新浪日 K
  -> 清洗日 K，并分离盘中 bar 与已完成日 K
  -> 计算均线、量价指标和所有确定性规则证据
  -> 根据 ANALYZER / WATCHLIST / POSITION 场景裁剪模块
  -> 组织一次 DeepSeek 结构化请求
  -> 校验并合并各子项 AI 文本
  -> 返回版本化模块报告
```

当前 `StockAnalyzerServiceImpl` 中的行情读取、均线计算、规则计算、AI 提示组装和结果装配应按职责拆分为可独立测试的单元。实现可以继续位于 RuoYi 单体模块内，不引入新部署服务或消息队列。

### 3.2 场景上下文

分析服务接收显式场景上下文：

- `ANALYZER`：单股分析页；
- `WATCHLIST`：自选股分析；
- `POSITION`：持仓分析，额外携带成本价、数量和账户总资产。

持仓金额、实时市值、浮动盈亏和持仓比例必须在调用 DeepSeek 前计算完成。不能继续由 Controller 在 AI 调用后补充 `holding`，否则止损和止盈 AI 无法获得完整上下文。

### 3.3 前端复用

新增共用 `StockAnalysisReport` 组件。三个页面只维护输入、请求、列表展开、加载和错误状态，报告组件负责模块裁剪、证据展示、AI 文本和响应式布局。现有股票模块公共 SCSS 继续承载颜色、卡片、指标网格和状态样式。

## 4. 响应模型

`StockAnalysisResult` 改为版本化模块报告，结构如下：

```text
StockAnalysisResult
|- schemaVersion
|- scene
|- stockCode / stockName
|- analyzedAt
|- realtimeQuoteTime
|- completedBarDate
|- basicInfo
|- trend
|- buyPoints[]
|- stopLoss[]
|- takeProfit[]
|- forbiddenMistakes[]
`- holding
```

其中：

- `basicInfo`、`trend` 和 `forbiddenMistakes` 始终返回；
- `buyPoints` 仅在趋势为 `UP` 时返回，否则字段为空或省略，前端不渲染该模块；
- `stopLoss` 和 `takeProfit` 仅在 `POSITION` 场景返回；
- `holding` 仅在 `POSITION` 场景返回。

每个可判定子项使用统一模型：

```text
RuleAnalysis
|- code
|- title
|- status
|- conclusion
|- evidence[]
`- aiAnalysis
```

`status` 只允许：

- `MATCHED`：规则全部满足；
- `NOT_MATCHED`：规则不满足；
- `PENDING`：需要后续交易日确认；
- `INSUFFICIENT_DATA`：行情数据不足以判定。

每条 `evidence` 包含稳定键、中文名称、实际值、展示单位、规则阈值、通过状态和解释。数值使用原始精度参与计算，只在输出层格式化。前端不得根据展示文本重新推导规则状态。

`schemaVersion` 用于识别持仓历史快照。缺少版本或版本不兼容的旧快照不按新报告渲染，页面显示“历史报告版本过旧，请重新分析”。本次不迁移数据库中的旧 JSON。

## 5. 数据时点与基础信息

### 5.1 日 K 完成口径

- 所有均线和规则只使用已完成日 K。
- Asia/Shanghai 交易日 15:10 前，若日 K 包含当天 bar，必须把它视为盘中数据并从规则序列排除。
- 15:10 后只有在行情源已提供当天 bar 时才纳入规则序列。
- 周末或节假日使用最近一个可用交易日，不要求本次改造接入额外交易日历。
- 响应同时展示实时行情时间和规则使用的最后完成交易日，避免用户混淆实时价格与规则价格。

### 5.2 基础信息模块

基础信息展示：

- 实时当前价格；
- 最近已完成交易日 MA5；
- 最近已完成交易日 MA10；
- 最近已完成交易日 MA20；
- 腾讯实时行情提供的标准盘中量比；
- 当日截至当前成交量 ÷ 前一已完成交易日成交量；
- 实时行情时间；
- 规则使用的最后完成交易日；
- AI 基础盘面概述。

当日成交量比应优先使用同一行情口径下的当天 bar 与前一完成 bar，避免不同数据源的股数/手数单位不一致。除数为零或数据缺失时返回空值和明确状态，不返回无穷大或伪造的零。

标准量比字段缺失时显示“暂无”，不得用当日成交量比替代。

## 6. 趋势规则

比较最近完成交易日的 MA20 与 3 个已完成交易日前的 MA20：

```text
MA20变化率 = (当前MA20 - 3个交易日前MA20) / 3个交易日前MA20 * 100%
```

- 变化率大于 `+0.15%`：`UP`，向上；
- 变化率位于 `[-0.15%, +0.15%]`：`FLAT`，走平；
- 变化率小于 `-0.15%`：`DOWN`，向下。

正负边界值均归入走平。模块展示两个 MA20 值、变化额、变化率、比较窗口、阈值、确定性趋势结论和 AI 趋势分析。只有 `UP` 才允许输出找买点模块。

## 7. 找买点

找买点模块包含三个独立子项。即使某个买点不满足，也要展示其完整指标证据、未满足原因和 AI 分析，不能只返回命中的主信号。

### 7.1 金叉买点

全部条件通过才为 `MATCHED`：

1. MA20 趋势为 `UP`；
2. 前一完成交易日 `MA5 <= MA20`，当前完成交易日 `MA5 > MA20`；
3. 当前 MA5、MA20 均高于各自前一完成交易日值；
4. 当前完成交易日收盘价同时站上 MA5 和 MA20；
5. 当前完成交易日成交量不低于此前 5 个完成交易日平均成交量的 1.5 倍。

证据至少展示交叉前后 MA5/MA20、两线方向、收盘价与两线位置、前 5 日均量、当前成交量和放量倍数。

### 7.2 回踩买点

全部条件通过才为 `MATCHED`：

1. 最近 20 个完成交易日内存在一次有效金叉；
2. 金叉之后阶段最高价相对金叉收盘价至少上涨 3%；
3. 回踩最低价或收盘价距离当日 MA20 不超过 2%；
4. 未有效跌破 MA20；若曾收盘跌破，必须在当天或下一交易日重新收回；
5. 回踩日成交量相对回踩前 5 日均量减少 50% 至 70%，即剩余量为基准的 30% 至 50%；
6. 确认日为阳线，成交量高于前一日，并重新收盘站上 MA5。

等待下一交易日收回或等待确认阳线时返回 `PENDING`，不能提前标记为买点。证据展示有效金叉日期、金叉后最大涨幅、距 MA20 比例、收回状态、缩量比例、确认 K 线和 MA5 位置。

### 7.3 均线粘合发散买点

全部条件通过才为 `MATCHED`：

1. 突破前连续 5 个完成交易日，`abs(MA5 - MA20) / MA20 <= 1%`；
2. 当前 MA5 由下向上穿越 MA20，且两条均线均向上；
3. MA20 趋势为 `UP`；
4. 当前成交量不低于此前 5 日均量的 1.5 倍；
5. 当前收盘价突破此前 20 个完成交易日震荡区间最高价。

证据展示连续粘合天数、粘合期均线距离、交叉前后数据、两线方向、前 5 日均量、放量倍数、前 20 日震荡上沿和突破幅度。

## 8. 持仓止损与止盈

止损和止盈只在持仓页计算和展示。持仓上下文包括成本价、数量、成本金额、当前市值、浮动盈亏额、浮动盈亏比例、账户总资产和持仓比例。账户总资产缺失或非正数时，持仓比例返回空值，不阻断其他规则。

### 8.1 短线止损

满足任一条件即触发：

- 浮动盈亏比例不高于 `-5%`；
- 连续两个完成交易日收盘价低于各自 MA5。

展示成本价、规则参考价格、浮动盈亏比例、`-5%` 阈值，以及最近两个完成交易日的收盘价和 MA5。

### 8.2 趋势止损

当前完成交易日收盘价跌破 MA20，且成交量达到此前 5 日均量的 1.5 倍时触发，确定性结论为清仓。展示收盘价、MA20、当前成交量、前 5 日均量和放量倍数。

### 8.3 常规止盈

持仓盈利达到 `3%` 至 `5%` 或更高，并且不满足强势延续时触发分批止盈。展示成本价、规则参考价格、浮盈比例、止盈区间和强势延续状态。

### 8.4 强势止盈

强势延续满足以下条件：

- 最近两个完成交易日均为阳线；
- 两日各自成交量均不低于其此前 5 日均量的 1.2 倍；
- MA5 高于 MA20；
- MA5 与 MA20 的间距持续扩大。

满足时结论为继续持有，直到出现死叉或更高优先级止损。死叉定义为前一日 `MA5 >= MA20`、当前日 `MA5 < MA20`。展示最近两日开收盘、各自放量倍数、两线关系、间距变化和死叉状态。

### 8.5 冲突优先级

为了避免止盈结论覆盖止损，持仓最终纪律按以下优先级判断：

1. 趋势止损；
2. 短线止损；
3. 常规止盈；
4. 强势持有；
5. 普通持有或观望。

所有子项仍完整展示，但模块摘要和 AI 提示必须服从该优先级。

## 9. 六个错误

每份报告固定输出以下六条，不调用 AI 改写：

1. 只看金叉，不看 20 日线趋势；
2. 无量金叉就进场；
3. 回踩时放量下跌；
4. 震荡市频繁操作；
5. 不止损，心存幻想；
6. 盈利后贪心不止盈。

前端使用两行三列警示卡展示，并保留 `doc/520.txt` 中每条错误的后果说明。窄屏下自动降为两列和一列。

## 10. DeepSeek 结构化分析

### 10.1 单次请求

每次分析最多调用一次 DeepSeek。提示内容只包含：

- 股票代码和名称；
- 数据时点；
- 当前场景应显示的标准化指标；
- 各规则状态、实际证据和服务器结论；
- 持仓场景的成本、数量、盈亏和仓位信息。

不发送用户 ID、用户名或其他身份信息。

### 10.2 返回结构

DeepSeek 必须返回 JSON，对应当前场景存在的模块，例如：

```json
{
  "basicInfo": "基础盘面概述",
  "trend": "趋势分析",
  "buyPoints": {
    "GOLDEN_CROSS": "金叉分析",
    "RETRACE": "回踩分析",
    "CONVERGENCE_BREAKOUT": "粘合发散分析"
  },
  "stopLoss": {
    "SHORT_TERM": "短线止损分析",
    "TREND": "趋势止损分析"
  },
  "takeProfit": {
    "REGULAR": "常规止盈分析",
    "STRONG": "强势止盈分析"
  }
}
```

普通或自选场景不要求返回止损、止盈；趋势非向上时不要求返回 `buyPoints`。

### 10.3 校验与降级

- 服务器校验 JSON 类型、允许字段和文本长度，兼容模型偶尔添加的 Markdown 代码围栏。
- AI 文本只能写入 `aiAnalysis`，不能覆盖 `status`、`conclusion` 或 `evidence`。
- 单个字段缺失时只把对应子项标记为“AI 分析暂不可用”，其余 AI 内容继续使用。
- 未配置 Key、超时、限流、非 JSON 或完全失败时，技术报告仍成功，所有 AI 区域显示明确的不可用原因。
- 日志不得输出 API Key、认证头或包含完整持仓上下文的提示全文。

## 11. 前端页面设计

### 11.1 共用报告布局

采用已确认的纵向完整报告：

1. 基础信息：核心指标网格和 AI 概述；
2. 定趋势：比较公式、实际值、变化率、趋势徽标和 AI 分析；
3. 找买点：三个子卡片，每张上半部为证据、下半部为 AI 分析；
4. 止损：短线止损和趋势止损两张子卡片；
5. 止盈：常规止盈和强势止盈两张子卡片；
6. 六个错误：两行三列固定警示卡。

状态除颜色外必须同时有文字或图标语义。长 AI 文本自动换行。桌面、768px 和 375px 宽度下不能出现非表格区域的横向溢出。

### 11.2 AI 分析页

点击“开始分析”直接请求完整报告。保留股票代码输入、回车触发、路由股票代码参数、加载和错误状态。加载期间显示当前阶段说明，但不伪造进度百分比。

### 11.3 我的自选

点击某行“分析”后调用完整分析并展开报告。单独点击展开图标时，如果当前内存中没有报告，只显示“点击分析生成最新报告”，不得自动调用 DeepSeek。删除现有二次 AI 按钮。

### 11.4 我的持仓

展开持仓行时可以读取已保存的新版本快照，不产生行情或 AI 调用。点击“分析”后获取最新行情、生成包含止损和止盈的完整报告并覆盖快照。旧版快照显示重新分析提示。删除现有二次 AI 按钮。

### 11.5 并发与旧响应

每只股票或持仓保留请求版本号。重复触发时只有最新请求可以更新页面，旧请求完成后不得覆盖新报告。加载状态按行隔离，并在请求完成或失败后可靠复位。

## 12. 异常与降级

- 腾讯实时行情失败、日 K 可用：基础信息中的实时字段显示不可用，以最近完成收盘价作为非实时参考；规则继续计算。
- 新浪日 K 失败、实时行情可用：基础信息正常；趋势、止损和止盈保留模块结构但返回 `INSUFFICIENT_DATA`，不生成买点模块。
- 两个行情源都失败：本次分析失败，前端保留输入和旧报告并展示稳定业务错误。
- 历史 bar 不足：受影响的子项返回 `INSUFFICIENT_DATA`，其他模块继续展示。
- 除六个固定错误外，前端不得硬编码补造指标、状态或 AI 文本。
- Controller 不向客户端返回外部 URL、第三方响应原文、堆栈或内部异常细节。

## 13. 测试与验收

### 13.1 后端单元测试

使用固定日 K fixture 覆盖：

- 日 K 排序、去重、盘中 bar 排除和完成日期；
- MA5、MA10、MA20 计算及输出精度；
- MA20 向上、走平、向下和正负 `0.15%` 等号边界；
- 有效、无量、逆势金叉；
- 已确认、待确认和失效回踩；
- 满足和不满足突破条件的粘合发散；
- `-5%`、连续两日跌破 MA5、放量跌破 MA20；
- 常规止盈、强势延续、死叉及持仓纪律优先级；
- 标准量比和当日/前日成交量比互不替代；
- `ANALYZER`、`WATCHLIST`、`POSITION` 的模块裁剪；
- DeepSeek 只调用一次、JSON 正常解析、部分字段缺失和完全失败降级；
- 旧快照版本识别。

规则单元测试不访问真实网络或 DeepSeek。

### 13.2 服务与接口测试

- 验证行情单源失败时的部分报告；
- 验证持仓上下文在 AI 调用前已计算；
- 验证 DeepSeek 失败仍可返回和保存技术报告；
- 验证持仓快照覆盖、用户隔离和非法业务 ID；
- 验证客户端不能通过场景或持仓参数分析其他用户的数据；
- 验证稳定错误消息不泄露第三方响应和内部异常。

### 13.3 前端与构建验收

- 三个页面均不再存在二次 AI 按钮或前端 `includeAi` 分支；
- 趋势非向上时不显示找买点；
- 只有持仓页显示止损和止盈；
