# 我的持仓移除操作设计

## 背景

“我的持仓”已有新增、编辑和分析能力。后端服务与 Mapper 已具备按 `position_id + user_id` 删除持仓的基础方法，菜单 SQL 也已定义 `stock:position:remove` 权限，但尚未开放 Controller 删除接口，前端也没有删除 API 与操作入口。

持仓分析快照表没有外键级联。若只删除持仓，会留下无法再访问的孤立分析记录，因此移除操作必须同时清理对应快照。

## 交互设计

- 在“我的持仓”表格右侧操作栏中，将红色文字按钮“移除”与“编辑”“分析”并列展示。
- 按钮受现有 `stock:position:remove` 权限控制。
- 点击后显示二次确认框，内容包含股票名称和代码，并明确提示将同步删除已保存的分析记录。
- 用户确认后调用删除接口；取消时不产生任何请求和状态变化。
- 删除成功后：
  - 若该持仓正在展开，立即清除其展开状态。
  - 清理该持仓在页面中的报告、加载状态、AI 状态和请求版本缓存。
  - 刷新持仓列表与持仓比例展示。
- 删除失败时保留当前页面状态，由现有请求错误处理展示错误信息，用户可再次尝试。

## 后端设计

- 新增 `DELETE /stock/position/{id}`。
- 接口权限为 `stock:position:remove`，用户 ID 始终取当前登录用户。
- `StockPositionServiceImpl.remove(userId, id)` 在同一事务中：
  1. 删除当前用户、当前持仓对应的分析快照。
  2. 删除当前用户的持仓记录。
  3. 若持仓不存在或不属于当前用户，抛出“position not found”，并回滚快照删除。
- 账户总资产设置不随持仓移除而改变。

## 数据访问

- `StockPositionAnalysisSnapshotMapper` 新增按 `userId + positionId` 删除方法。
- SQL 删除条件必须同时包含 `user_id` 与 `position_id`，防止跨用户操作。
- 不修改现有表结构，不新增外键或迁移脚本。

## 验证

- 后端服务测试验证快照和持仓均被删除。
- 后端服务测试验证持仓不存在时抛错且事务方法具备回滚边界。
- Controller 契约验证删除路由与 `stock:position:remove` 权限。
- 前端契约验证删除 API、权限按钮、确认提示、成功后的缓存清理和列表刷新。
- 运行相关 Maven 测试、前端契约测试和生产构建。
