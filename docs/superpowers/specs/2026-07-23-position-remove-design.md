# 我的持仓移除操作设计

## 背景

“我的持仓”已有新增、编辑和分析能力，但缺少移除入口。持仓分析快照表没有外键级联，因此移除持仓时也必须清理对应快照，并处理“分析请求尚未完成、删除已发生”的并发场景。

## 交互设计

- 在“我的持仓”表格右侧操作栏增加红色文字按钮“移除”，受 `stock:position:remove` 权限控制。
- 点击后显示二次确认，包含股票名称、代码，并提示已保存的分析记录也会删除。
- 用户取消时不发请求、不改变页面状态。
- 删除成功后，清除该行的展开状态、报告、加载状态、AI 状态及请求版本缓存，然后刷新持仓列表和比例展示。
- 删除失败时保留当前页面状态，由现有错误处理展示原因。
- 账户总资产设置不随持仓移除而改变。

## 后端与数据设计

- 新增 `DELETE /stock/position/{id}`，权限为 `stock:position:remove`，用户 ID 始终取当前登录用户。
- `StockPositionServiceImpl.remove(userId, id)` 在同一事务中：
  1. 按 `id + userId` 删除持仓；不存在或不属于当前用户时抛出 `position not found`，且不触碰快照。
  2. 按 `userId + positionId` 删除分析快照。
- 快照写入使用基于 `stock_position` 的条件式 `INSERT ... SELECT`。只有所属用户的持仓仍存在时才保存分析结果，避免慢速分析请求在持仓删除后重新生成孤立快照。
- 所有删除及存在性判断都同时包含用户 ID 与持仓 ID，防止跨用户操作。
- 不修改表结构，不新增外键或迁移脚本。

## 并发保证

- 分析先保存、删除后执行：删除事务先删持仓，再删已有快照。
- 删除先完成、分析后返回：条件式快照写入匹配不到持仓，不产生记录。
- 分析保存与删除交错：对同一持仓记录的数据库访问由事务和行锁排序，最终状态均为持仓与快照同时不存在。
