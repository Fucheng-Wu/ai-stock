# 股票列表分析展开按钮设计

## 背景与问题

“我的自选”和“我的持仓”已经使用 Element UI 表格的展开行展示分析结果，但展开列被设置为 `width="1"`。这使最左侧的原生箭头及其点击区域几乎不可见、不可用，用户只能依赖右侧“分析/收起”文字按钮控制展开状态。

## 目标

- 在两张股票列表最左侧提供清晰、可点击的独立展开箭头。
- 收起时箭头向右，展开时箭头向下。
- 同一时间只允许展开一只股票；切换股票时自动收起上一只。
- 右侧继续保留“分析”按钮，用于发起或刷新分析，不再承担收起功能。

## 交互设计

### 左侧展开箭头

- 使用 Element UI 表格原生 `type="expand"` 列，恢复合理列宽和点击区域。
- 收起状态显示向右箭头，展开状态显示向下箭头。
- 点击当前股票箭头可在展开与收起之间切换。
- 点击另一只股票的箭头时，收起之前的股票并展开当前股票。
- 首次通过箭头展开时：
  - 自选页面请求一次基础技术分析。
  - 持仓页面优先读取已保存分析；未保存时展示现有的“立即分析”空状态。
- 已加载的数据继续缓存在页面状态中，再次展开不重复请求。

### 右侧分析操作

- “我的自选”和“我的持仓”右侧操作栏继续显示“分析”按钮。
- 按钮文案始终为“分析”，不再根据展开状态变成“收起”。
- 点击“分析”会发起或刷新当前股票的分析，并自动展开该股票的结果行。
- 收起操作只由最左侧箭头负责，避免一个按钮同时承担两个语义。

## 状态同步

- 两页继续使用单元素数组保存当前展开行键值。
- 监听表格原生展开事件，将 Element UI 内部展开状态同步到页面状态。
- 当展开新的股票时，用新键值替换旧键值，保证只展开一行。
- 请求失败时保留可操作的箭头和“分析”按钮，用户可再次尝试。

## 验证

- 源码测试验证两页展开列具有可用宽度并绑定展开事件。
- 验证右侧按钮文案始终为“分析”，不再显示“收起”。
- 验证箭头展开、再次点击收起、切换股票自动收起上一只。
- 验证首次加载和缓存复用逻辑不回归。
- 运行前端生产构建。
