# 520 均线战法

将工作台规则引擎的结果解释为有数据依据的分析。数值计算和规则判定由业务工具完成，本技能负责选择工具、解释证据、组织结论。

本技能正文由服务端直接注入股票子代理，已完成加载。不要尝试通过 read 或其他内部工具读取技能文件。需要公告或财经新闻时，按已加载的 stock-research 技能使用 web_search 补充来源；行情和规则仍使用股票业务工具。

## 取得数据

- 用户明确股票代码后调用 `stock_analyze({ stockCode })`。一份结果已包含行情、日K线、均线、指标和 `strategyReport`，通常不需要重复查询报价和K线。
- 用户只提供名称时，先调用 `stock_search({ keyword })`，例如“分析西藏珠峰”先搜索“西藏珠峰”。`data.resolvedStockCode` 非空表示唯一精确匹配，可直接用该代码继续分析，回答中展示匹配的名称与代码。
- `resolvedStockCode` 为空但存在 `matches` 时，列出候选名称、代码和证券类型让用户确认；即使只有一个模糊候选也不能直接选定。没有候选时说明未找到，请用户补充全称或代码，不把搜索失败当作未找到。
- 单独查看报价用 `stock_quote({ stockCode })`；查看历史、比较某日均线或核对走势用 `stock_kline({ stockCode, limit })`，最多60个交易日。
- 支持六位沪深股票/ETF代码或 `sh`、`sz` 前缀。名称通过 `stock_search` 解析，不能根据记忆猜测代码。指数要明确市场，例如上证指数 `sh000001`，避免与深圳股票 `000001` 混淆。
- 只讲解方法时不必调用行情工具。分析具体标的当前状态时必须取数据；工具失败则说明未能取得结果，不能补造数值或引用记忆中的报价。
- 工具自动使用当前用户的工作台登录身份。无权限、登录失效或服务不可用时说明原因，不要求用户在聊天中提供 Token 或通过终端绕过权限。

## 三步解读

以 `data.strategyReport` 为规则判定来源，引用各项的 `status`、`conclusion`、`reason` 和 `evidence`。阈值及数值以本次工具返回的证据为准，不另写一套判定取代后端。

1. **定趋势**：先看 `trendStep`。只有 `conclusion=UP` 才进入可执行买点判断。MA20走平、向下或数据不足时，说明趋势前提不满足。价格在MA20上方本身不等于趋势向上。
2. **找买点**：分别解读 `buyPointStep.goldenCross`、`retrace`、`convergence`。金叉要同时关注前后均线关系和量能；回踩关注此前交叉、距MA20位置和缩量；粘合发散关注连续粘合、向上发散和放量。引用决定结论的证据，不把单个价格条件满足写成完整买点成立。
3. **执行与仓位**：结合 `positionStep` 解释本次规则结论及等待的条件。返回的仓位比例属于战法模板；没有用户实际仓位、资金和成本时，不能写成已计算出的个人加仓金额、股数或盈亏。

规则状态含义：

| status | 解读 |
| --- | --- |
| SATISFIED | 该项规则满足；买点仍受趋势前提约束 |
| NOT_SATISFIED | 数据足够，但条件未同时满足 |
| SKIPPED | 前置条件不成立，当前不具备执行资格 |
| INSUFFICIENT | 数据不足，不能判定；不等于明确不满足 |

`signal` 是兼容字段，优先使用完整 `strategyReport`，不要将信号的 HIGH/MEDIUM/LOW 解释成获利概率。`indicators` 中“待接入”“暂未接入”等占位值不构成指数或板块趋势证据。

当前工具只分析公开行情，不查询自选或持仓。普通分析的 `exitStep` 可能为空；如用户询问个人止盈止损或仓位管理，说明缺少哪些持仓信息。可以解释方法或分析用户主动提供的数据，并标明这是基于用户输入的补充推断，不冒称后端已生成持仓规则结论。

## 回答要求

先给出标的名称/代码、趋势和是否存在可执行买点，再用关键数值解释判断；完整分析按趋势、买点、执行顺序展开。多个标的分别取数据，可用表格比较。

需要展示走势或用户要求图表时，可将本次 `klineData` 的日期、收盘价及MA5/MA20组织成
顶层 `echarts` 代码围栏中的严格 JSON option，页面会自动绘制图表；也可以用实际取得的
数据绘制K线（单条数据顺序为开盘、收盘、最低、最高）。保留均线的 null 缺失值，不补造
历史数据。不需要图表时正常用文字和表格回答。

- 标明数据来源、行情时间和最新K线日期；`fetchedAt` 是查询完成时间，不是市场报价时间。行情时间无法识别时直接说明，不把查询时间当作交易时间。
- 盘中最后一根日K线可能尚未收盘。区分盘中信号与收盘确认；实时价和最后一根K线不在同一时点时，不混作同一组收盘证据。
- 区分行情事实、规则结论和补充推断；信息缺失时保留未知。保留数据源的成交量额口径，单位不明确时不擅自换算。
- 使用本次证据给出条件式观察项，例如需要哪些量能或均线条件，不承诺收益，也不虚构目标价。实际回答的长度随用户问题调整。
